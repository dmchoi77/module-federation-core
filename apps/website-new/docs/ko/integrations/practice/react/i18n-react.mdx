# React 마이크로 프론트엔드에서 Module Federation으로 국제화(i18n) 구현하기

:::tip 데모 참고
예제 프로젝트는 여기에서 확인할 수 있습니다: [React i18n](https://github.com/module-federation/module-federation-examples/tree/master/i18next-nextjs-react)
:::

## 개요

마이크로 프론트엔드에서는 각 애플리케이션이 가능한 한 독립적으로 동작하는 것이 중요합니다. 하지만 애플리케이션 간 통신이 꼭 필요한 상황도 있습니다. 대표적인 예가 언어 설정 동기화입니다. 사용자가 한 애플리케이션에서 언어를 바꾸면, 통합된 모든 마이크로 프론트엔드에도 그 변경이 반영되어야 합니다. 이 문서에서는 Module Federation 기반 마이크로 프론트엔드 아키텍처에서 `react-i18next`로 국제화를 구현하는 전략을 설명합니다.

## 시나리오

두 애플리케이션을 가정해 보겠습니다. App A는 container 애플리케이션이고, App B는 remote 애플리케이션입니다. App B는 standalone 애플리케이션으로 독립 실행될 수 있지만, runtime에는 App A 안에 삽입될 수도 있습니다. 목표는 App A와 App B 사이의 언어 설정을 자연스럽게 동기화해 두 애플리케이션이 각자의 지역화 콘텐츠를 올바르게 관리하고 표시하도록 하는 것입니다.

## 아키텍처와 구현

### Bundler 설정 확장

마이크로 프론트엔드 통합을 위해 Webpack, Rspack, Rsbuild, Create React App(CRA)의 기존 설정을 Module Federation 플러그인으로 확장합니다. 이렇게 하면 코드베이스를 eject하지 않고도 App B가 컴포넌트, theme, hook 같은 요소를 노출하고, App A나 다른 통합 애플리케이션이 이를 사용할 수 있습니다.

### 국제화 설정

번역 기능의 중심에는 `react-i18next`가 있습니다. 먼저 `i18next` instance를 설정하고 메인 애플리케이션 파일(`App.js`)에서 직접 가져옵니다. 이 instance는 context store를 활용해 상태, 번역 리소스, 플러그인을 관리합니다.

#### 번역 덮어쓰기 문제 해결

각 애플리케이션이 같은 방식으로 `i18next` instance를 초기화하면 리소스 충돌이 생길 수 있습니다. 특히 번역 문구가 서로 덮어써지는 문제가 발생하기 쉽습니다. 이를 피하기 위해 App A와 App B에 별도의 `i18next` instance를 만들고, 각 애플리케이션이 자신의 번역 문구를 독립적으로 유지하도록 합니다.

### 구현 단계

#### i18next Instance 설정

App A와 App B 각각에 별도의 `i18next` instance를 다음처럼 설정합니다.

```javascript
// App A
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import enJSON from './translations/en';
import uaJSON from './translations/ua';

// 번역 리소스
const resources = {
  en: { translation: enJSON },
  ua: { translation: uaJSON },
};

// App A용 i18next instance 초기화
const appAInstance = i18n.createInstance();
appAInstance.use(initReactI18next).init({
  resources,
  lng: 'en', // 기본 언어
  fallbackLng: 'en',
  interpolation: { escapeValue: false },
  react: { useSuspense: true },
});

export default appAInstance;

// App B도 별도 instance로 비슷하게 설정
```

#### i18next Provider 통합

애플리케이션 컴포넌트를 `I18nextProvider`로 감싸고, 각 애플리케이션에 해당하는 `i18next` instance를 전달해 번역 context가 올바르게 적용되도록 합니다.

```javascript
// App A Wrapper
import { I18nextProvider } from 'react-i18next';
import appAInstance from '../i18n';

const AppAI18nWrapper = ({ children }) => (
  <I18nextProvider i18n={appAInstance}>{children}</I18nextProvider>
);

export default AppAI18nWrapper;

// App B도 비슷하게 설정
```

#### 언어 전환 로직

App B에서 언어 전환을 쉽게 처리할 custom hook을 작성합니다. 예를 들면 다음과 같습니다.

```javascript
import appBInstance from '../i18n';

const useSwitchLanguage = () => {
  return (languageId) => appBInstance.changeLanguage(languageId);
};

export default useSwitchLanguage;
```

App A나 다른 통합 애플리케이션에서 사용할 수 있도록 이 hook을 Module Federation으로 노출합니다.

```javascript
// Module Federation exposes configuration
exposes: {
  './hooks/useSwitchAppBLanguage': './src/hooks/useSwitchLanguage',
},
```

App A에서는 통합된 모든 마이크로 프론트엔드의 언어 전환을 조율하는 hook을 구현합니다.

```javascript
import useSwitchAppBLanguage from 'remoteAppB/hooks/useSwitchAppBLanguage';
import appAInstance from '../i18n';

const useSwitchLanguage = () => {
  const switchAppBLanguageHook = useSwitchAppBLanguage();
  //Application A
  const switchAppALanguage = (languageCode) => appAInstance.changeLanguage(languageCode);
  //Application B
  const switchAppBLanguage = (languageCode) => switchAppBLanguageHook(languageCode);
  //Both Applications
  const switchAllLanguages = (languageCode) => {
    switchAppALanguage(languageCode);
    switchAppBLanguage(languageCode);
  };

  return { switchAppALanguage, switchAppBLanguage, switchAllLanguages };
};

export default useSwitchLanguage;
```

### 언어 전환 인터페이스

모든 애플리케이션의 언어 변경을 실행할 수 있도록 버튼 같은 UI 컴포넌트를 구현합니다.

```javascript
import { useSwitchLanguage } from 'src/hooks/useSwitchLanguage';

const LanguageSwitcher = () => {
  const { switchAllLanguages } = useSwitchLanguage();
  const handleLanguageSwitch = (lng) => () => switchAllLanguages(lng);

  return <button onClick={handleLanguageSwitch("ua")}>Change language to Ukrainian</button>;
};

export default LanguageSwitcher;
```

#### 통합 환경 처리

언어 전환 컴포넌트를 조건부로 표시하려면, 예를 들어 App B가 App A 안에 삽입됐을 때 switcher를 숨기려면 `useIsRemote` 같은 사용자 정의 hook을 활용합니다.

`useIsRemote` hook은 현재 애플리케이션(App B 등)이 독립 실행 모드로 실행 중인지, 아니면 다른 애플리케이션(App A 등) 안에 삽입되어 있는지 판단합니다. 이 구분을 바탕으로 애플리케이션 context에 맞게 컴포넌트를 조건부 렌더링할 수 있습니다.

아래는 특정 조건을 확인해 애플리케이션 실행 환경을 판단하는 단순화된 `useIsRemote` hook 예시입니다. 실제 애플리케이션에서는 URL 매개변수, DOM 존재 여부, 또는 삽입 실행과 독립 실행을 구분할 수 있는 다른 신호를 기준으로 삼을 수 있습니다.

```javascript
import { useEffect, useState } from 'react';

/**
 * 현재 애플리케이션이 remote(삽입된 상태)로 실행 중인지,
 * 아니면 독립 실행 애플리케이션으로 실행 중인지 판단합니다.
 *
 * 애플리케이션 구조에 맞게 이 로직을 조정하세요. 예를 들어 URL 매개변수나
 * 삽입된 상태에서만 존재하는 특정 DOM 엘리먼트를 확인할 수 있습니다.
 */
const useIsRemote = () => {
  const [isRemote, setIsRemote] = useState(false);

  useEffect(() => {
    // 삽입 상태를 나타내는 URL 매개변수 확인
    const searchParams = new URLSearchParams(window.location.search);
    setIsRemote(searchParams.has('embedded'));

    // 또는 전역 변수나 특정 DOM 엘리먼트 확인
    // setIsRemote(window.parent !== window || document.getElementById('embed-flag') !== null);
  }, []);

  return isRemote;
};

export default useIsRemote;
```

#### useIsRemote Hook 사용

`useIsRemote` hook을 구현했다면, 컴포넌트 안에서 이를 사용해 애플리케이션이 standalone으로 실행 중인지 embedded 상태인지에 따라 요소를 조건부 렌더링할 수 있습니다. 다음은 App B에서 언어 전환 컴포넌트를 조건부로 표시하는 예시입니다.

```javascript
import React from 'react';
import useIsRemote from './hooks/useIsRemote';
import LanguageSwitcher from './components/LanguageSwitcher';

const App = () => {
  const isRemote = useIsRemote();

  return (
    <div>
      {/* remote로 실행 중이 아닐 때만 LanguageSwitcher 표시 */}
      {!isRemote && <LanguageSwitcher />}
    </div>
  );
};

export default App;
```

이 예제에서 `LanguageSwitcher`는 `useIsRemote` hook이 판단한 `isRemote` 상태를 기준으로, App B가 App A 안에 삽입되지 않았을 때만 렌더링됩니다. 이런 방식은 언어 전환기 같은 컴포넌트를 필요한 context에서만 보여 주므로 사용자 경험을 개선하고 마이크로 프론트엔드 애플리케이션의 독립성도 유지할 수 있습니다.
