# Nx와 Module Federation

Nx는 모노레포와 특히 잘 어울리는 강력한 오픈소스 빌드 시스템입니다. Angular와 React 프로젝트를 위한 Module Federation 지원을 기본 제공합니다.

Module Federation에서 모노레포를 사용할 때의 장점을 아직 읽지 않았다면 먼저 [모노레포에서 Module Federation을 사용할 때의 장점](/integrations/framework/monorepos/index.html)을 확인하세요.

## Nx란 무엇인가요?

Nx는 개발 생산성을 높이고, CI 성능을 최적화하며, 코드 품질을 유지하는 데 필요한 도구와 기법을 제공하는 강력한 오픈소스 빌드 시스템입니다.
모노레포를 만들고 유지보수할 때뿐 아니라 Module Federation 프로젝트를 관리할 때도 잘 맞습니다.

### Nx의 핵심 기능

- 효율적인 작업 실행: Nx는 [작업을 병렬 실행](https://nx.dev/features/run-tasks)하고, 작업 간 의존성을 기준으로 실행 순서를 정합니다.
- CI 작업 분산: Nx는 여러 VM에 [작업을 분산](https://nx.dev/ci/features/distribute-task-execution)해 CI를 확장합니다. 저장소가 커져도 CI 속도를 유지할 수 있습니다.
- 로컬/원격 캐시: [로컬 캐시](https://nx.dev/features/cache-task-results)와 [원격 캐시](https://nx.dev/ci/features/remote-cache)를 사용해 불필요한 작업 재실행을 막고 개발 시간과 CI 시간을 줄입니다.
- E2E 테스트 분할과 flaky 테스트 재실행: Nx는 큰 e2e 테스트를 [자동으로 분할](https://nx.dev/ci/features/split-e2e-tasks)해 여러 VM에 분산합니다. 또한 [flaky e2e 테스트를 식별하고 재실행](https://nx.dev/ci/features/flaky-tasks)할 수 있습니다.
- 의존성 업데이트 자동화: [Nx 플러그인](https://nx.dev/concepts/nx-plugins)을 활용하면 [코드 생성](https://nx.dev/features/generate-code)과 코드베이스/의존성 [자동 업그레이드](https://nx.dev/features/automate-updating-dependencies) 같은 기능을 사용할 수 있습니다.
- 높은 확장성: Nx는 커스터마이징하기 쉽고 확장 가능합니다. [조직 전용 플러그인](https://nx.dev/extending-nx/tutorials/organization-specific-plugin)이나 [툴링 플러그인](https://nx.dev/extending-nx/tutorials/tooling-plugin)을 만들어 팀에 맞게 조정할 수 있습니다.

## Nx Module Federation 기능

Nx는 Angular와 React 프로젝트를 위한 Module Federation 지원을 기본 제공합니다. Server Side Rendering(SSR)을 사용하는 프로젝트도 포함됩니다.

### Module Federation 프로젝트 생성을 위한 generator

Nx generator는 프로젝트를 일관되고 편리하게 스캐폴딩하는 방법을 제공합니다. [Angular(`@nx/angular`)](https://nx.dev/nx-api/angular)와 [React(`@nx/react`)](https://nx.dev/nx-api/react)용 Nx 플러그인에는 Module Federation 프로젝트를 빠르게 만들고 Consumer (host)와 Producer (remote)를 쉽게 추가할 수 있는 generator가 포함되어 있습니다.

아래는 Nx `consumer` generator 예시입니다.

```bash
# 세 개의 Producer를 포함한 Angular Consumer 애플리케이션 생성
nx g @nx/angular:consumer shell --producers=products,cart,checkout

# 세 개의 Producer를 포함한 React Consumer 애플리케이션 생성
nx g @nx/react:consumer shell --producers=products,cart,checkout
```

[Angular](/integrations/framework/angular/using-nx-for-angular.html)와 [React](/integrations/practice/react/using-nx-for-react.html) 가이드에서 Nx로 Module Federation을 설정하는 방법을 더 자세히 볼 수 있습니다.

### Executor

Nx는 Module Federation 애플리케이션을 빌드하고 실행하기 위한 executor를 제공합니다. 특히 중요한 것은 로컬에서 애플리케이션을 실행할 때 사용하는 `module-federation-dev-server` executor입니다. 이 executor는 다음 기능을 제공합니다.

- Consumer (host) 프로젝트와 모든 Producer (remote)를 하나의 명령으로 함께 실행합니다. 리소스 관리와 DX를 고려한 방식입니다.
- 현재 작업 중인 개별 Producer (remote)를 HMR과 파일 감시로 실행해 로컬 개발을 빠르게 합니다.

아래 [개발자 경험(DX) 확장](#scaling-developer-experience-dx) 섹션에서 Nx가 Module Federation의 개발 경험을 어떻게 확장하는지 더 볼 수 있습니다.

Nx는 Consumer (host) 프로젝트와 모든 Producer (remote)를 하나의 명령으로 실행합니다. 덕분에 Producer (remote) 프로젝트 변경이 시스템의 다른 프로젝트에 영향을 주는지 즉시 피드백을 받을 수 있습니다.
또한 배포된 애플리케이션을 실제 사용자가 사용하는 흐름과 같은 방식으로 [사용자처럼 개발](#develop-as-a-user)할 수 있습니다.

Nx가 `module-federation-dev-server` executor로 이 흐름을 어떻게 구현하는지는 [Nx Module Federation Technical Overview](https://nx.dev/concepts/module-federation/nx-module-federation-technical-overview)를 참고하세요.

### 개발자 경험(DX) 확장

Nx는 `module-federation-dev-server` executor를 활용해 빠른 개발 주기를 유지합니다. dev server가 빠르게 시작되도록 다음 방식을 사용합니다.

- Module Federation 시스템 안의 각 프로젝트 빌드 산출물에 [로컬 캐시](https://nx.dev/features/cache-task-results)를 제공합니다.
- 각 프로젝트 빌드 산출물에 [원격 캐시](https://nx.dev/ci/features/remote-cache)를 제공해, 다른 팀이 만든 캐시도 활용할 수 있습니다. 특정 Producer (remote)를 직접 작업하지 않는 팀에게 특히 중요합니다.
- Producer (remote) 빌드를 병렬 실행해 빌드 과정을 빠르게 합니다. _(사용 가능한 캐시 산출물이 있으면 그것을 사용합니다.)_
- dev server와 함께 실행할 Producer (remote)를 지정할 수 있어 감시해야 하는 파일 수를 줄입니다.
- 모놀리식 빌드를 더 작은 단위로 나누고 `affected` 명령으로 변경 영향을 받은 프로젝트의 작업만 실행합니다.

_참고: 원격 캐싱은 [Nx Cloud](https://nx.dev/nx-cloud)에서 제공합니다._

### 사용자처럼 개발하기

좋은 DX와 정확한 Module Federation 아키텍처 개발을 위해 Nx는 전체 구성을 하나의 애플리케이션처럼 바라보는 방식을 권장합니다. 즉 Consumer (host)와 모든 Producer (remote)가 합쳐져 하나의 애플리케이션을 이룹니다.

Consumer (host)는 진입점이고, Producer (remote)는 애플리케이션이 사용하는 모듈입니다. 다만 Producer (remote)는 애플리케이션 번들에 포함되는 대신 런타임에 네트워크를 통해 가져옵니다.

이를 지원하고 좋은 로컬 DX를 제공하기 위해, Nx의 Module Federation 지원은 로컬 개발 시 항상 Consumer (host) 애플리케이션을 실행하는 흐름을 기준으로 설계되어 있습니다. 이렇게 하면 전체 Module Federation 아키텍처가 시작됩니다. Consumer (host)는 webpack-dev-server로 실행되고, 각 Producer (remote)는 단일 HTTP 서버를 통해 실행됩니다. 자세한 내용은 [Nx Module Federation Technical Overview](https://nx.dev/concepts/module-federation/nx-module-federation-technical-overview)를 참고하세요.

특정 Producer (remote) 애플리케이션을 작업 중이라면 `--devProducers` 옵션으로 현재 개발 중인 Producer (remote)를 지정하세요. 예: `nx serve shell --devProducers=checkout`. 그러면 해당 Producer (remote)가 webpack-dev-server로 실행되어 HMR과 live reloading을 사용할 수 있습니다.

## Nx가 지원하는 사용 사례

### 마이크로 프론트엔드 아키텍처

Nx는 애플리케이션을 독립적으로 배포해야 하는 팀에 마이크로 프론트엔드 아키텍처를 권장합니다. 독립 배포 가능성은 조직 안의 각 팀이 다른 팀과 무관하게 자기 릴리스 주기에 맞춰 작업물을 배포할 수 있는 개념입니다. Module Federation으로 이를 구현할 수 있으며, 조직과 애플리케이션이 커질수록 더 매력적인 선택지가 됩니다.

Module Federation을 사용하면 각 팀은 필요할 때 배포할 수 있는 Producer (remote)를 소유할 수 있고, Consumer (host) 애플리케이션은 이를 예상한 방식대로 소비합니다. 따라서 전체를 다시 배포하지 않고도 특정 Producer (remote)를 업데이트할 수 있습니다.
이 구조는 마이크로 프론트엔드 접근과 잘 맞습니다.

자세한 내용은 Nx 문서의 [Micro Frontend Architecture](https://nx.dev/concepts/module-federation/micro-frontend-architecture)를 참고하세요.

### 더 빠른 빌드

Module Federation은 애플리케이션을 런타임에 필요한 더 작은 배포 단위로 나눌 수 있게 해 줍니다. 이 특성을 활용하면 애플리케이션 빌드 시간을 줄일 수 있습니다.

여러 작은 애플리케이션의 빌드를 병렬로 실행하고 함께 배포할 수 있습니다. 단일 릴리스 주기와 팀 간 조율은 유지하면서도, 로컬 개발 환경과 CI 모두에서 빌드 시간을 줄일 수 있습니다.

Nx 워크스페이스에 [Nx Cloud](https://nx.dev/nx-cloud)를 추가하면 다른 팀원이나 CI가 만든 빌드 캐시도 사용할 수 있어 빌드 시간을 더 줄일 수 있습니다.

자세한 내용은 Nx 문서의 [Faster Builds](https://nx.dev/concepts/module-federation/faster-builds-with-module-federation)를 참고하세요.
