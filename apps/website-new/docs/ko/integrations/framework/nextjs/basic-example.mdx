## 환경 설정

시작하기 전에 [Node.js](https://nodejs.org/)를 설치하고 Node.js 버전이 16 이상인지 확인하세요. **Node.js 20 LTS 사용을 권장합니다.**

현재 사용 중인 Node.js 버전은 다음 명령으로 확인할 수 있습니다.

```bash
node -v
```

현재 환경에 Node.js가 설치되어 있지 않거나 설치된 버전이 너무 낮다면 [nvm](https://github.com/nvm-sh/nvm) 또는 [fnm](https://github.com/Schniz/fnm)으로 필요한 버전을 설치할 수 있습니다.

아래는 nvm으로 Node.js 20 LTS를 설치하는 예시입니다.

```bash
# Node.js 20 LTS 버전을 설치합니다.
nvm install 20 --lts

# 새로 설치한 Node.js 20을 기본 버전으로 설정합니다.
nvm alias default 20

# 새로 설치한 Node.js 20으로 전환합니다.
nvm use 20
```

### Local Webpack 환경 설정

"Local Webpack"은 Webpack을 의존성으로 직접 설치해야 한다는 뜻입니다. 이 경우 Next.js는 Webpack 내부 API를 모두 노출하지 않는 내장 Webpack 사본을 사용하지 않습니다.

```bash title="shell"
cross-env NEXT_PRIVATE_LOCAL_WEBPACK=true next dev
# or
cross-env NEXT_PRIVATE_LOCAL_WEBPACK=true next build
```

`.env`로도 설정할 수 있지만, `NEXT_PRIVATE_LOCAL_WEBPACK`이 필요한 시점에 맞춰 적용되지 않을 수 있어 불안정할 수 있습니다.

```ini title=".env"
NEXT_PRIVATE_LOCAL_WEBPACK=true
```

## 단계 3: SSR 구현

<Steps>

### 서버 라이프사이클 추가

Next.js가 서버 런타임을 생성하게 하려면 `_document`에서 `getInitialProps` 또는 `getServerSideProps`를 구현해야 합니다.



<div className="rspress-directive warning">
서버 라이프사이클 메서드가 없으면 Next는 정적이라고 판단한 페이지를 `SSG`로 처리하려고 합니다.

서버 런타임이 없으면 업데이트된 remote를 렌더링할 서버도 없습니다.
</div>

```jsx title="_document.js"
import Document, { Html, Head, Main, NextScript } from 'next/document';

class MyDocument extends Document {
  static async getInitialProps(ctx) {
    const initialProps = await Document.getInitialProps(ctx);
    return initialProps;
  }

  render() {
    return (
      <Html>
        <Head />
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    );
  }
}
```



### Node 핫 리로드를 위한 재검증 추가

remote 모듈 업데이트를 처리하려면 `revalidate` 함수를 사용합니다. Webpack은 청크 캐시를 사용하므로 이미 로드된 청크를 다시 가져오지 않고, 실행 중인 서버도 업데이트를 자동으로 인식하지 못하기 때문입니다.

재검증을 구현하는 대표적인 방식은 두 가지입니다.
- 렌더링 차단
- 응답 후 재검증

<Tabs>
  <Tab label="렌더링 차단">
    대부분의 경우 이 구현을 권장합니다. 서버와 클라이언트가 항상 동기화되도록 해 hydration 오류를 피하는 데 도움이 되기 때문입니다. 렌더링 전에 흐름을 잠시 막고 업데이트를 확인하면, 사용자 경험에 큰 영향을 주지 않으면서 애플리케이션을 최신 상태로 유지할 수 있습니다.

    **동작 방식:**

    - **Page 렌더링 전에** 서버가 사용 가능한 업데이트가 있는지 확인합니다.
    - **업데이트가 있으면** 클라이언트 요청에 응답하기 전에 Hot Module Replacement(HMR)를 진행합니다.
    - **이 방식은** 서버 렌더링 결과와 클라이언트 렌더링 결과의 불일치 없이 모든 사용자가 최신 애플리케이션을 받도록 보장합니다.

    **구현 예시:**

    ```jsx title="_document"

    import { revalidate } from '@module-federation/nextjs-mf/utils';
    import Document, { Html, Head, Main, NextScript } from 'next/document';

    class MyDocument extends Document {
      static async getInitialProps(ctx) {
        if (ctx?.pathname && !ctx?.pathname?.endsWith('_error')) {
          await revalidate().then((shouldUpdate) => {
            if (shouldUpdate) {
              console.log('Hot Module Replacement (HMR) activated', shouldUpdate);
            }
          });
        }

        const initialProps = await Document.getInitialProps(ctx);
        return initialProps;
      }

      render() {
        return (
          <Html>
            <Head />
            <body>
              <Main />
              <NextScript />
            </body>
          </Html>
        );
      }
    }
    ```
  </Tab>
  <Tab label="응답 후 재검증">
    hydration error가 발생할 수 있어 권장되지는 않지만, 응답 객체의 `finish` 이벤트를 수신한 뒤 업데이트를 확인하는 방식도 사용할 수 있습니다. 업데이트를 덜 자주 적용해도 되거나 서버와 클라이언트의 즉시 일관성이 아주 중요하지 않은 특정 상황에서 유용할 수 있습니다.

    **동작 방식:**

    - **클라이언트에 응답한 뒤** 서버가 응답 객체의 `finish` 이벤트를 수신합니다.
    - **응답 전송이 끝나면** 업데이트를 확인합니다.
    - **업데이트가 있으면** 로그를 남기거나 필요한 작업을 수행합니다. 다만 업데이트는 이후 요청부터 적용됩니다.

    **구현 예시:**

   ```jsx title="_document"
    static async getInitialProps(ctx) {
      const initialProps = await Document.getInitialProps(ctx);
      ctx?.res?.on('finish', () => {
        revalidate().then((shouldUpdate) => {
          console.log('Response sent, checking for updates:', shouldUpdate);
        });
      });
      return initialProps;
    }
    ```
  </Tab>
</Tabs>

### 청크 플러싱

청크 플러싱은 SSR 중 사용된 청크를 모아 브라우저로 보낼 `<script>` 태그를 생성하는 과정입니다.

```jsx title="_document"
import Document, { Html, Head, Main, NextScript } from 'next/document';
import {
  revalidate,
  FlushedChunks,
  flushChunks,
} from '@module-federation/nextjs-mf/utils';

class MyDocument extends Document {
  static async getInitialProps(ctx) {
    if (ctx.pathname) {
      if (!ctx.pathname.endsWith('_error')) {
        await revalidate().then((shouldUpdate) => {
          if (shouldUpdate) {
            console.log('should HMR', shouldUpdate);
          }
        });
      }
    }

    const initialProps = await Document.getInitialProps(ctx);

    const chunks = await flushChunks();

    return {
      ...initialProps,
      chunks,
    };
  }

  render() {
    return (
      <Html>
        <Head>
          <FlushedChunks chunks={this.props.chunks} />
        </Head>
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    );
  }
}
```
</Steps>

페이지 파일에 라이프사이클 메서드를 하나 추가하세요.

```javascript
export const getServerSideProps = async () => {
  return {
    props: {}
  }
}
// or
Index.getInitialProps = async ()=> {
  return {}
}

export default Index;
```
