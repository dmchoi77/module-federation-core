# Angular Module Federation에서 서버 사이드 렌더링 사용하기

초기 Module Federation은 주로 Single Page Application(SPA)에 유용한 Client-Side Rendering(CSR) 중심으로 사용되었습니다. 하지만 웹 개발 환경이 발전하면서 여러 장점을 가진 Server-Side Rendering(SSR)의 중요성도 점점 커졌습니다.

## Nx 15.4부터 지원된 Module Federation SSR

Nx 15.4부터 SSR을 지원하는 Module Federation이 도입되었고, 이는 중요한 변화였습니다. Nx workspace에서 Module Federation과 SSR을 함께 사용하면 두 기술의 장점을 모두 활용할 수 있습니다.

Nx와 Module Federation 통합을 더 깊이 이해하려면 공식 Nx 문서를 함께 보는 것을 권장합니다. 이 기술들을 효과적으로 활용하는 데 필요한 설명과 실용적인 가이드를 제공합니다.

- [Module Federation에 대한 공식 Nx 문서](https://nx.dev/recipes/module-federation)

이 가이드는 Angular 애플리케이션에서 Server-Side Rendering과 Module Federation을 함께 설정하는 방법에 집중합니다.

## 동작 방식

전통적인 SSR 애플리케이션에서는 브라우저가 요청한 라우트에 맞춰 서버가 애플리케이션을 렌더링합니다. Module Federation과 SSR을 함께 사용하면 이 개념이 확장됩니다. 특정 라우트가 remote 모듈을 가리키는 경우, host 서버가 해당 라우트 처리를 remote 서버에 위임하고 remote 서버가 HTML을 렌더링해 브라우저로 돌려줍니다.

이 통합 방식은 SSR의 장점을 활용하면서도 빌드를 더 작은 단위로 나누는 유연성을 유지합니다. 애플리케이션 안의 기능을 독립적으로 배포할 수 있어, host 서버 전체를 다시 배포하지 않고도 remote 서버만 업데이트할 수 있습니다.

## 단계별 가이드

먼저 `dashboard`라는 host 애플리케이션과 `login`이라는 remote 애플리케이션을 만들어 보겠습니다.

<Steps>

### Nx 워크스페이스 생성

다음 명령으로 새 Nx 워크스페이스를 생성합니다.

```bash
npx create-nx-workspace@latest myorganization
```

생성 과정에서 워크스페이스 타입과 프리셋을 묻는 프롬프트가 표시됩니다.

다음과 같이 응답합니다.

```bash
- Workspace type: "integrated"
- Workspace content: "apps"
- Enable distributed caching (CI speed enhancement): "No"
```

**Nx Cloud 선택 사항**

workspace를 설정하는 동안 Nx Cloud를 추가할지 묻는 질문도 나옵니다. 이 가이드에서는 Nx Cloud를 다루지 않지만, Module Federation과 함께 사용하면 팀과 CI에서 캐시를 공유해 빌드 시간을 줄이는 데 도움이 됩니다. 자세한 내용은 [Nx Cloud 웹사이트](https://nx.app)에서 확인하세요.

### Nx Angular 플러그인 설치

workspace를 만든 뒤 해당 디렉터리로 이동합니다.

```bash
cd myorganization
```

#### 공식 Nx Angular 플러그인 설치

```bash
npm install @nx/angular
```


### 애플리케이션 생성

다음 명령 하나로 SSR을 포함한 Module Federation 아키텍처를 생성합니다.

```bash
npx nx g host dashboard --remotes=login --ssr
```

이 명령은 두 개의 Angular Universal(SSR) 애플리케이션을 만들고, 브라우저와 서버 양쪽 Webpack을 Module Federation에 맞게 설정합니다.


### 애플리케이션 실행

1. `dashboard`(host)와 `login`(remote) 애플리케이션을 실행하려면 다음 명령을 실행합니다.

```bash
npx nx serve-ssr dashboard
```

이 명령은 `login` 애플리케이션의 브라우저 번들과 서버 번들을 빌드한 뒤 Node.js로 실행합니다. 단, `login` 애플리케이션은 file watcher 없이 실행되므로 코드 변경이 자동으로 반영되지는 않습니다.
</Steps>

## 캐싱과 실시간 업데이트

- Nx는 `login` 애플리케이션의 브라우저 번들과 서버 번들 빌드를 캐싱합니다. 이후 실행에서는 애플리케이션을 다시 빌드하는 대신 이 캐시를 사용합니다.
- `dashboard` 애플리케이션의 서버 빌드에는 file watcher가 포함되어 있어 코드 변경을 실시간으로 반영할 수 있습니다.

## 설정 확인

1. 컴파일이 성공하면 서버가 수신 중인 주소를 알려주는 성공 메시지가 표시됩니다. 일반적으로 `http://localhost:4200`입니다.
2. 브라우저에서 이 주소를 열고 DevTools의 Network 탭을 확인합니다.

### Module Federation 동작 확인

- 처음에는 Angular Universal이 렌더링을 처리하고, 이후 내비게이션은 Client-Side Rendering(CSR)으로 전환됩니다.
- `http://localhost:4200/login`으로 이동하면 login 페이지의 서버 렌더링 HTML을 확인할 수 있습니다. 이를 통해 Module Federation이 remote 서버의 모듈을 해석하고 렌더링할 수 있음을 확인할 수 있습니다.

### Login 애플리케이션의 실시간 업데이트

`login` 애플리케이션을 작업 중이고 변경 결과를 실시간으로 확인해야 한다면, 코드 변경 시 서버 rebuild가 일어나도록 설정할 수 있습니다. `devRemotes` flag를 사용하면 됩니다.

```bash
npx nx serve-ssr dashboard --devRemotes=login
```

이 명령을 사용하면 변경할 때마다 서버가 `login` 애플리케이션을 다시 빌드합니다. 덕분에 반복 작업이 더 빠르고 효율적입니다.
