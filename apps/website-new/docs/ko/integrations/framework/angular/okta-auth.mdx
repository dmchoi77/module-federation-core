# Module Federation에서 OpenID Connect 인증 통합

## 소개

Module Federation은 마이크로 프론트엔드 사이에서 공유 코드와 상태를 더 쉽게 관리할 수 있게 합니다. 이 가이드에서는 Okta와 OpenID Connect를 사용해 프로젝트에 인증을 추가하는 방법을 설명합니다. 문서를 끝까지 따라 하면 기존 애플리케이션과 새로 통합한 마이크로 프론트엔드 모두에서 인증 상태를 다룰 수 있습니다.

## 사전 준비

- 무료 Okta 개발자 계정이 필요합니다. 계정이 없다면 Okta CLI로 가입할 수 있습니다.
- 로컬 머신에 Okta CLI가 설치되어 있어야 합니다.

## Okta 인증 설정

### Okta 애플리케이션 생성

<Steps>
### Okta 가입 또는 로그인:

- 새 계정을 등록하려면 터미널에서 `okta register`를 실행합니다.
- 이미 계정이 있다면 `okta login`으로 로그인합니다.

### 애플리케이션 생성:

- `okta apps create`를 실행합니다.
- 프롬프트가 표시되면 기본 애플리케이션 이름을 사용하거나 새 이름을 입력합니다.
- *Single-Page App(SPA)* 을 선택하고 Enter를 눌러 확인합니다.
- *Redirect URI*에는 `http://localhost:4200/login/callback`을 사용하고, Logout *Redirect URI*는 `http://localhost:4200`으로 설정합니다.
</Steps>

### Okta에서 애플리케이션 설정

Okta CLI는 Okta Org에 OIDC SPA를 만들고, redirect URI를 설정하며, Everyone group에 접근 권한을 부여하고, `http://localhost:4200`을 trusted origin으로 추가합니다.

:::tip 참고
앱 생성에는 *Okta Admin Console*을 사용할 수도 있습니다. Angular 앱은 Angular 애플리케이션 생성에 대한 Okta 문서를 참고하세요.
:::

**Okta 애플리케이션 설정 예제:**

- *Issuer:* `https://dev-12345.okta.com/oauth2/default`
- *Client ID:* `0oab12345CDEF`

:::tip 참고
*Issuer*와 *Client ID*를 꼭 기록해 두세요. 애플리케이션 설정에 필요한 중요한 값입니다.
:::

### 필수 라이브러리 설치

프로젝트에 Okta Angular와 Okta Auth JS 라이브러리를 추가합니다.

```bash
npm install @okta/okta-angular@5.2 @okta/okta-auth-js@6.4
```

### Angular 모듈에서 Okta 설정

shell 프로젝트의 `AppModule`에서 `OktaAuthModule`과 `OktaAuth`를 가져와 설정합니다. `{yourOktaDomain}`과 `{yourClientID}`는 실제 Okta domain과 client ID로 바꿉니다.

```typescript
import { NgModule } from '@angular/core';
import { OKTA_CONFIG, OktaAuthModule } from '@okta/okta-angular';
import { OktaAuth } from '@okta/okta-auth-js';

const oktaAuth = new OktaAuth({
  issuer: 'https://{yourOktaDomain}/oauth2/default',
  clientId: '{yourClientID}',
  redirectUri: window.location.origin + '/login/callback',
  scopes: ['openid', 'profile', 'email']
});

@NgModule({
  imports: [
    OktaAuthModule,
    // other imports
  ],
  providers: [
    { provide: OKTA_CONFIG, useValue: { oktaAuth } }
  ],
  // other module properties
})
```

### 인증을 위한 라우팅 설정

로그인 콜백 라우트가 포함되도록 `app-routing.module.ts`를 업데이트합니다.

```typescript
import { Routes } from '@angular/router';
import { OktaCallbackComponent } from '@okta/okta-angular';

const routes: Routes = [
  { path: '', component: ProductsComponent },
  { path: 'basket', loadChildren: () => import('mfeBasket/Module').then(m => m.BasketModule) },
  { path: 'login/callback', component: OktaCallbackComponent }
];
```

## 인증 로직 구현

### 애플리케이션 컴포넌트 업데이트

Okta 라이브러리를 사용해 sign-in과 sign-out 로직을 포함하도록 `app.component.ts`를 수정합니다. 인증 상태 변수도 이에 맞게 업데이트합니다.

```typescript
import { Component, Inject } from '@angular/core';
import { Observable } from 'rxjs';
import { filter, map, shareReplay } from 'rxjs/operators';
import { OKTA_AUTH, OktaAuthStateService } from '@okta/okta-angular';
import { OktaAuth } from '@okta/okta-auth-js';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  public isAuthenticated$: Observable<boolean>;
  public name$: Observable<string>;

  constructor(private oktaStateService: OktaAuthStateService, @Inject(OKTA_AUTH) private oktaAuth: OktaAuth) {
    this.isAuthenticated$ = this.oktaStateService.authState$
      .pipe(
        filter(authState => !!authState),
        map(authState => authState.isAuthenticated ?? false),
        shareReplay()
      );

    this.name$ = this.oktaStateService.authState$
      .pipe(
        filter(authState => !!authState && !!authState.isAuthenticated),
        map(authState => authState.idToken?.claims.name ?? '')
      );
  }

  public async signIn(): Promise<void> {
    await this.oktaAuth.signInWithRedirect();
  }

  public async signOut(): Promise<void> {
    await this.oktaAuth.signOut();
  }
}
```

### UI에서 Sign-In과 Sign-Out 처리

`app.component.html`에 sign-in과 sign-out 버튼을 위한 UI 로직을 추가합니다.

```html
<li>
  <button *ngIf="(isAuthenticated$ | async) === false; else logout" (click)="signIn()">
    Sign In
  </button>

  <ng-template #logout>
    <button (click)="signOut()">
      Sign Out
    </button>
  </ng-template>
</li>
```

### 애플리케이션 테스트

`npm run start` 또는 현재 구성에 맞는 명령으로 프로젝트를 실행해 인증 기능을 테스트합니다. 구현이 정상이라면 사용자는 로그인과 로그아웃을 할 수 있고, 로그인 후 프로필 정보에도 접근할 수 있습니다.

## Module Federation으로 사용자 프로필 추가하기

이 섹션에서는 Module Federation을 적용해 메인 애플리케이션과 마이크로 프론트엔드 전반에서 인증 상태를 공유하는 방법을 확장해서 살펴봅니다. 새 Angular 애플리케이션을 만들고, 라우팅을 설정하고, 프로필 세부 정보를 포함하도록 컴포넌트를 업데이트합니다.

<Steps>
### 새 Angular 애플리케이션 생성

현재 실행 중인 프로젝트를 중지하고 다음 명령으로 `mfe-profile`이라는 새 Angular 애플리케이션을 생성합니다.

```bash
ng generate application mfe-profile --routing --style css --inline-style --skip-tests
```

이 명령은 다음 작업을 수행합니다.

- 모듈과 컴포넌트를 포함한 새 애플리케이션을 생성합니다.
- 별도의 라우팅 모듈을 추가합니다.
- CSS 스타일을 컴포넌트 안에 인라인으로 정의합니다.
- 초기 컴포넌트의 테스트 파일 생성을 건너뜁니다.

### HomeComponent와 ProfileModule 생성

`mfe-profile` 애플리케이션 안에 `HomeComponent`와 `ProfileModule`을 만들려면 다음 명령을 실행합니다.
```bash
ng generate component home --project mfe-profile
ng generate module profile --project mfe-profile --module app --routing --route profile
```

이 명령은 다음 항목을 만듭니다.

- 기본 라우트에 사용할 `HomeComponent`
- 라우팅과 기본 `ProfileComponent`를 포함하며, `AppModule`에 lazy loading 라우트로 추가되는 `ProfileModule`
</Steps>

### 애플리케이션 코드 업데이트
<Steps>
### 라우팅 설정

`HomeComponent` 라우트와 `ProfileModule`의 lazy loading 라우트를 포함하도록 `projects/mfe-profile/src/app/app-routing.module.ts`를 업데이트합니다.

```typescript
const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'profile', loadChildren: () => import('./profile/profile.module').then(m => m.ProfileModule) }
];
```

### AppComponent와 HomeComponent 템플릿 업데이트

- `app.component.html`에서는 기존 내용을 원하는 메시지와 내비게이션용 `router-outlet`으로 바꿉니다.
- `home.component.html`에서는 `/profile`로 이동하는 router link와 함께 Profile 페이지로 안내하는 메시지를 제공합니다.

</Steps>

### Profile 컴포넌트 설정
<Steps>
 ### Profile 로직 구현
`OktaAuthStateService`를 사용해 사용자 프로필 정보와 인증 상태를 위한 속성이 포함되도록 `projects/mfe-profile/src/app/profile/profile.component.ts`를 업데이트합니다.

### Profile 템플릿 업데이트

이름, 이메일, 마지막 로그인 시간 같은 사용자 프로필 세부 정보를 표시하도록 템플릿을 수정합니다.
</Steps>

### Module Federation 통합
<Steps>
### `mfe-profile`에 Module Federation 추가

`@angular-architects/module-federation` schematic을 사용해 `mfe-profile`을 Module Federation에 맞게 준비하고, 포트는 `4202`로 지정합니다.

```bash
ng add @angular-architects/module-federation --project mfe-profile --port 4202
```

### `mfe-profile`을 remote로 설정

host 애플리케이션에서 사용할 수 있도록 `mfe-profile`의 `webpack.config.js`를 업데이트해 `ProfileModule`을 노출합니다.

### host 애플리케이션 설정 업데이트
shell 애플리케이션의 `webpack.config.js`를 수정해 `mfe-profile`을 remote로 포함합니다. 이렇게 하면 host가 Profile 마이크로 프론트엔드에 접근할 수 있습니다.

### 인증 상태 공유

- shell 애플리케이션의 `webpack.config.js`를 업데이트해 Okta 라이브러리를 singleton으로 공유합니다.
- `mfe-profile`도 Okta 라이브러리를 공유하도록 설정해 인증 상태를 함께 사용할 수 있게 합니다.
</Steps>
### 통합된 애플리케이션 실행

Module Federation을 설정하고 shell과 마이크로 프론트엔드 애플리케이션을 모두 업데이트했다면 `npm run run:all`로 프로젝트를 실행할 수 있습니다.

이 설정을 통해 로그인, 프로필 확인, 로그아웃은 물론 메인 애플리케이션과 마이크로 프론트엔드 전반의 다른 기능도 자연스럽게 사용할 수 있습니다.
