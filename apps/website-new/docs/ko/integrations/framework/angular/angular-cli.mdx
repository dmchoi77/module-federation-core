# Angular CLI 설정

이 가이드는 Angular CLI에 Module Federation을 통합하는 방법을 설명합니다. 이 통합에는 `@angular-architects/module-federation` 플러그인을 사용합니다.

## 사전 준비

- **Angular CLI**: 버전 10 이상이 필요합니다.
- **플러그인 설치**: `@angular-architects/module-federation` 플러그인을 설치합니다.

## 설치


  먼저 빌드 단계에서 Module Federation을 사용할 수 있도록 Angular CLI를 설정합니다.
  Module Federation 기능을 제대로 사용하려면 사용자 정의 builder가 필요합니다.

  `@angular-architects/module-federation` 패키지는 이 사용자 정의 builder를 제공합니다.
  `ng add` 명령으로 프로젝트에 추가합니다.

  <Tabs>
    <Tab label="Angular CLI">
      ```bash
      ng add @angular-architects/module-federation --project shell --port 4200 --type host
      ng add @angular-architects/module-federation --project mfe1 --port 4201 --type remote
      ```
    </Tab>
    <Tab label="Nx Cli">
      Nx를 사용한다면 절차가 조금 다릅니다.

      ```bash
      npm i @angular-architects/module-federation -D
      ng g @angular-architects/module-federation:init --project shell --port 4200 --type host
      ng g @angular-architects/module-federation:init --project mfe1 --port 4201 --type remote
      ```

    </Tab>
  </Tabs>
  <div className={"rspress-directive tip"}>
    14.3 버전에서 도입된 `--type` 인자는 필요한 설정만 생성되도록 합니다.
  </div>

## Shell (Host) 설정

Shell (Host)는 Module Federation 통합에서 핵심 역할을 합니다.
이 섹션에서는 라우팅을 통해 `FlightModule`을 lazy-loading할 수 있도록 Shell을 설정합니다.
<Steps>
  ### 라우팅 설정

  먼저 가상 경로를 사용해 lazy-loaded `FlightModule`을 지정하는 애플리케이션 라우트를 정의합니다.

  ```javascript
  export const APP_ROUTES: Routes = [
    {
      path: '',
      component: HomeComponent,
      pathMatch: 'full'
    },
    {
      path: 'flights',
      loadChildren: () => import('mfe1/Module').then(m => m.FlightsModule)
    },
  ];
  ```

  이 설정에서 `'mfe1/Module'` 경로는 가상 경로입니다. Shell 애플리케이션 안에 실제 파일로 존재하는 것이 아니라, 별도 프로젝트의 모듈을 가리키는 참조입니다.

### TypeScript 타입 지정

가상 경로에 대한 타입 정의를 만듭니다.

```typescript
// decl.d.ts
declare module 'mfe1/Module';
```

이 정의를 추가하면 TypeScript 컴파일러가 가상 경로를 이해할 수 있습니다.

### Webpack 설정

`mfe1`로 시작하는 모든 경로를 remote 프로젝트로 해석하도록 Webpack에 알려줍니다. 이 설정은 `webpack.config.js` 파일에서 처리합니다.

```javascript
const { shareAll, withModuleFederationPlugin } = require('@angular-architects/module-federation/webpack');

module.exports = withModuleFederationPlugin({

   remotes: {
     "mfe1": "http://localhost:4201/remoteEntry.js",
   },

   shared: {
     ...shareAll({ singleton: true, strictVersion: true, requiredVersion: 'auto' }),
   },

});
```
  `remotes` 섹션에서는 `mfe1` 경로를 remote 마이크로 프론트엔드의 진입점에 매핑합니다. Webpack이 생성하는 이 진입점에는 마이크로 프론트엔드와 상호작용하는 데 필요한 정보가 들어 있습니다.

<details>

  개발 환경에서는 remote entry URL을 하드코딩해도 충분합니다. 하지만 프로덕션에서는 동적인 접근이 필요합니다. 동적 remote 개념은 별도의 동적 remote 문서에서 더 자세히 다룹니다.

  - `shared` 속성은 Shell과 마이크로 프론트엔드 사이에서 공유할 npm 패키지를 지정합니다. `shareAll` helper를 사용하면 `package.json`에 있는 모든 의존성을 공유합니다. 빠르게 설정하기에는 편하지만, shared dependencies가 너무 많아져 최적화 관점에서는 부담이 될 수 있습니다.
  - `singleton: true`와 `strictVersion: true`를 함께 설정하면 shell과 마이크로 프론트엔드 사이에 버전 불일치가 있을 때 Webpack이 런타임 오류를 발생시킵니다. `strictVersion`을 `false`로 바꾸면 런타임 경고만 발생합니다.
  - `@angular-architects/module-federation` 플러그인이 제공하는 `requiredVersion: 'auto'` 옵션은 `package.json`에서 버전을 자동으로 찾아 버전 관련 문제를 줄이는 데 도움을 줍니다.
</details>
</Steps>


## remote 설정

Module Federation에서 remote라고도 부르는 마이크로 프론트엔드는 일반 Angular 앱과 비슷한 구조를 가집니다. `AppModule`에는 고유 라우트가 있고, 항공편 관련 기능은 `FlightsModule`이 담당합니다. 이 섹션에서는 `FlightsModule`을 shell(host)에 자연스럽게 로드하는 방법을 설명합니다.

<Steps>
### 라우트 정의

`AppModule` 안에 기본 라우트를 정의합니다.

```typescript
export const APP_ROUTES: Routes = [
     { path: '', component: HomeComponent, pathMatch: 'full'}
 ];
```

이 단순한 라우팅 설정은 애플리케이션에 접근했을 때 `HomeComponent`로 이동하게 합니다.

### Module 생성

항공편 관련 작업을 처리할 `FlightsModule`을 생성합니다.

```typescript
@NgModule({
   imports: [
     CommonModule,
     RouterModule.forChild(FLIGHTS_ROUTES)
   ],
   declarations: [
     FlightsSearchComponent
   ]
 })
 export class FlightsModule { }
```

이 모듈은 다음처럼 정의된 `FlightsSearchComponent` 라우트를 포함합니다.

```typescript
export const FLIGHTS_ROUTES: Routes = [
     {
       path: 'flights-search',
       component: FlightsSearchComponent
     }
 ];
```

### Webpack 설정으로 Modules expose하기

Shell에서 `FlightsModule`을 로드할 수 있도록 Remote의 Webpack 설정에서 해당 모듈을 expose합니다.

```javascript
const { shareAll, withModuleFederationPlugin } = require('@angular-architects/module-federation/webpack');

module.exports = withModuleFederationPlugin({
   name: 'mfe1',
   exposes: {
     './Module': './projects/mfe1/src/app/flights/flights.module.ts',
   },
   shared: {
     ...shareAll({ singleton: true, strictVersion: true, requiredVersion: 'auto' }),
   },
});
```

<details>
이 설정에서:

- `name` 속성은 이 마이크로 프론트엔드를 `mfe1`로 식별합니다.
- `exposes` 속성은 `FlightsModule`을 `Module`이라는 공개 이름으로 expose해 Shell에서 사용할 수 있게 합니다.
- `shared` 속성은 Shell과 공유할 라이브러리를 나열합니다. `shareAll` 메서드를 사용하면 `package.json`의 모든 의존성을 공유합니다. `singleton: true`는 shared libraries의 단일 버전만 사용하게 하고, `strictVersion: true`는 버전이 맞지 않을 때 런타임 오류를 발생시킵니다.
</details>

</Steps>

## 애플리케이션 시작

Shell (Host)과 Micro-frontend (Remote)를 설정했으니, Module Federation 통합이 자연스럽게 동작하는지 테스트할 차례입니다.

Shell과 Micro-frontend를 시작하려면 다음 명령을 사용합니다.

```bash
ng serve shell -o
ng serve mfe1 -o
```

Shell의 Flights 섹션으로 이동하면 Micro-frontend가 동적으로 로드되는 것을 확인할 수 있습니다.

:::tip
이 플러그인은 `ng-add`와 `init` schematic을 실행할 때 `run:all` npm script를 설치합니다. 이 script로 모든 애플리케이션을 동시에 실행할 수 있습니다.

```bash
npm run run:all
# or
npm run run:all shell mfe1
```
:::


## Optimizing Dependency Sharing

`shareAll`을 사용하는 초기 설정은 간단하고 잘 동작하지만, 불필요하게 큰 shared bundles를 만들 수 있습니다.

shared dependencies를 더 효과적으로 관리하려면 `shareAll` 대신 `share` helper를 사용하는 방식을 고려하세요. 어떤 의존성을 공유할지 더 세밀하게 제어할 수 있습니다.

```javascript
// shareAll 대신 share를 사용합니다.
const { share, withModuleFederationPlugin } = require('@angular-architects/module-federation/webpack');

module.exports = withModuleFederationPlugin({
    // 공유할 패키지를 지정합니다.
    shared: share({
        "@angular/core": { singleton: true, strictVersion: true, requiredVersion: 'auto' },
        "@angular/common": { singleton: true, strictVersion: true, requiredVersion: 'auto' },
        "@angular/common/http": { singleton: true, strictVersion: true, requiredVersion: 'auto' },
        "@angular/router": { singleton: true, strictVersion: true, requiredVersion: 'auto' },
    })
});
```

이 설정에서는 `share` helper로 선택한 패키지만 명시적으로 공유합니다. 덕분에 번들 공유를 더 최적화하고 로딩 시간을 줄일 수 있습니다.
