## 재시도 플러그인

재시도 플러그인은 Module Federation을 위한 안정적인 재시도 메커니즘을 제공합니다. remote 모듈이나 리소스 로딩에 실패하면 자동으로 재시도해 애플리케이션을 더 안정적으로 유지합니다.

## 기능

- **자동 재시도**: 실패한 리소스 로딩을 재시도해 안정성을 높입니다.
- **도메인 순환**: 여러 백업 도메인 사이를 자동으로 전환합니다.
- **캐시 우회**: 재시도 시 쿼리 매개변수를 추가해 캐시 간섭을 피합니다.
- **유연한 설정**: 재시도 횟수, 지연 시간, 콜백을 조정할 수 있습니다.

## 설치

```bash
npm install @module-federation/retry-plugin
```

## 마이그레이션 가이드

### v0.18.x에서 v0.19.x로 마이그레이션

플러그인 설정이 단순해졌습니다. 기존 `fetch`와 `script` 설정 객체는 더 이상 권장되지 않습니다.

```ts
// ❌ Old way (deprecated)
RetryPlugin({
  fetch: {
    url: 'http://localhost:2008/not-exist-mf-manifest.json',
    fallback: () => 'http://localhost:2001/mf-manifest.json',
  },
  script: {
    url: 'http://localhost:2001/static/js/async/src_App_tsx.js',
    customCreateScript: (url, attrs) => { /* ... */ },
  }
})

// ✅ New way
RetryPlugin({
  retryTimes: 3,
  retryDelay: 1000,
  domains: ['http://localhost:2001'],
  manifestDomains: ['http://localhost:2001'],
  addQuery: ({ times, originalQuery }) => `${originalQuery}&retry=${times}`,
})
```

## 사용법

### 방법 1: 빌드 플러그인에서 사용

```ts title="rspack.config.ts"
import { pluginModuleFederation } from '@module-federation/rsbuild-plugin';
import { defineConfig } from '@rsbuild/core';

export default defineConfig({
  plugins: [
    pluginReact(),
    pluginModuleFederation({
      runtimePlugins: [
        path.join(__dirname, './src/runtime-plugin/retry.ts'),
      ],
    }),
  ],
});

```

```ts
// ./src/runtime-plugin/retry.ts
import { RetryPlugin } from '@module-federation/retry-plugin';
const retryPlugin = () => RetryPlugin({
  retryTimes: 3,
  retryDelay: 1000,
  manifestDomains: ['https://domain1.example.com', 'https://domain2.example.com'],
  domains: ['https://cdn1.example.com', 'https://cdn2.example.com'],
  addQuery: ({ times, originalQuery }) => `${originalQuery}&retry=${times}`,
  onRetry: ({ times, url }) => console.log('retry', times, url),
  onSuccess: ({ url }) => console.log('success', url),
  onError: ({ url }) => console.log('error', url),
})
export default retryPlugin;
```

### 방법 2: 순수 런타임에서 사용

```ts
import { createInstance, loadRemote } from '@module-federation/enhanced/runtime';
import { RetryPlugin } from '@module-federation/retry-plugin';

const mf = createInstance({
  name: 'federation_consumer',

      domains: ['https://cdn1.example.com', 'https://cdn2.example.com'],
      addQuery: ({ times, originalQuery }) => `${originalQuery}&retry=${times}`,
      onRetry: ({ times, url }) => console.log('retry', times, url),
      onSuccess: ({ url }) => console.log('success', url),
      onError: ({ url }) => console.log('error', url),
    }),
  ],
});
```

## 설정

### 기본

**retryTimes**

- 타입: `number`
- 선택 사항
- 재시도 횟수입니다. 기본값은 3입니다.

**retryDelay**

- 타입: `number`
- 선택 사항
- 재시도 사이의 지연 시간입니다. 밀리초 단위이며 기본값은 1000입니다.

### 고급

**domains**

- 타입: `string[]`
- 선택 사항
- 도메인 순환에 사용할 백업 도메인 목록입니다. 기본값은 빈 배열입니다.

**addQuery**

- 타입: `boolean | ((context: { times: number; originalQuery: string }) => string)`
- 선택 사항
- 재시도할 때 쿼리 매개변수를 추가할지 설정합니다. 기본값은 `false`입니다.
- 함수를 전달하면 재시도 횟수와 원래 쿼리 문자열을 받아 새 쿼리 문자열을 반환해야 합니다.

**fetchOptions**

- 타입: `RequestInit`
- 선택 사항
- 사용자 정의 fetch 옵션입니다. 기본값은 빈 객체입니다.

**manifestDomains**

- 타입: `string[]`
- 선택 사항
- Manifest(예: `mf-manifest.json`)를 가져올 때 사용할 도메인 순환 목록입니다. Manifest fetch 재시도에서는 `domains`보다 우선합니다. 그 외 리소스는 계속 `domains`를 사용합니다.

### 콜백

**onRetry**

- 타입: `({ times, domains, url, tagName }: { times?: number; domains?: string[]; url?: string; tagName?: string }) => void`
- 선택 사항
- 각 재시도마다 호출됩니다.
- 매개변수: `times` 현재 재시도 횟수, `domains` 도메인 목록, `url` 요청 URL, `tagName` 리소스 타입

**onSuccess**

- 타입: `({ domains, url, tagName }: { domains?: string[]; url?: string; tagName?: string; }) => void`
- 선택 사항
- 재시도 끝에 성공했을 때 호출됩니다.
- 매개변수: `domains` 도메인 목록, `url` 요청 URL, `tagName` 리소스 타입

**onError**

- 타입: `({ domains, url, tagName }: { domains?: string[]; url?: string; tagName?: string; }) => void`
- 선택 사항
- 모든 재시도가 실패했을 때 호출됩니다.
- 매개변수: `domains` 도메인 목록, `url` 요청 URL, `tagName` 리소스 타입

## 세부 정보

### 재시도 로직

리소스 로딩에 실패하면 플러그인이 자동으로 재시도합니다. 재시도 횟수는 `retryTimes`로 제어합니다. 예를 들면 다음과 같습니다.

- `retryTimes: 3`은 최초 시도 이후 최대 3번 더 재시도한다는 뜻입니다.
- 각 재시도 전에는 `retryDelay` ms만큼 대기합니다.

### 도메인 순환

`domains`를 설정하면 재시도할 때마다 host를 순환합니다.

```javascript
const retryPlugin = RetryPlugin({
  domains: [
    'https://cdn1.example.com',
    'https://cdn2.example.com',
    'https://cdn3.example.com'
  ],
});
```

시도 순서는 다음과 같습니다.

1. 최초 시도: 원래 URL
2. 첫 번째 재시도: `cdn2.example.com`으로 전환
3. 두 번째 재시도: `cdn3.example.com`으로 전환
4. 세 번째 재시도: `cdn1.example.com`으로 전환

### 캐시 우회

재시도 중 캐시 간섭을 피하려면 `addQuery`로 쿼리 매개변수를 추가하세요.

```javascript
const retryPlugin = RetryPlugin({
  addQuery: true, // adds ?retryCount=1, ?retryCount=2, etc.
});
```

함수를 직접 전달할 수도 있습니다.

```javascript
const retryPlugin = RetryPlugin({
  addQuery: ({ times, originalQuery }) => {
    return `${originalQuery}&retry=${times}&timestamp=${Date.now()}`;
  },
});
```

### 콜백

콜백을 사용하면 재시도 라이프사이클을 관찰할 수 있습니다.

```javascript
const retryPlugin = RetryPlugin({
  onRetry: ({ times, domains, url, tagName }) => {
    console.log(`Retry #${times}, domains: ${domains}, url: ${url}`);
  },
  onSuccess: ({ domains, url, tagName }) => {
    console.log(`Retry success, domains: ${domains}, url: ${url}`);
  },
  onError: ({ domains, url, tagName }) => {
    console.log(`Retry failed, domains: ${domains}, url: ${url}`);
  },
});
```

콜백 매개변수는 다음과 같습니다.

- `times`: 현재 재시도 횟수입니다. 1부터 시작합니다.
- `domains`: 현재 도메인 목록입니다.
- `url`: 현재 요청 URL입니다.
- `tagName`: 리소스 타입입니다. `'fetch'` 또는 `'script'`입니다.

## 사용 사례

### 1. CDN 페일오버

```javascript
const retryPlugin = RetryPlugin({
  retryTimes: 2,
  domains: [
    'https://cdn1.example.com',
    'https://cdn2.example.com',
    'https://cdn3.example.com'
  ],
  addQuery: true,
});
```

### 2. 불안정한 네트워크

```javascript
const retryPlugin = RetryPlugin({
  retryTimes: 5,
  retryDelay: 2000,
  onRetry: ({ times }) => {
    console.log(`Unstable network, retry #${times}`);
  },
});
```

### 3. 모니터링과 로깅

```javascript
const retryPlugin = RetryPlugin({
  onRetry: ({ times, url }) => {
    analytics.track('resource_retry', { times, url });
  },
  onError: ({ url }) => {
    logger.error('Resource load failed after all retries', { url });
  },
});
```

## 참고 사항

1. **성능**: 재시도 횟수가 많으면 로딩 시간이 늘어납니다. 환경에 맞게 조정하세요.
2. **도메인**: `domains`의 모든 도메인이 같은 리소스를 제공하는지 확인하세요.
3. **캐싱**: `addQuery`를 활성화했다면 CDN 캐싱 전략을 함께 고려하세요.
4. **오류 처리**: 모든 재시도가 실패하면 원본 오류가 throw됩니다. 상위에서 처리하세요.

## 오류 코드

- `RUNTIME_008`: 재시도 메커니즘을 트리거하는 리소스 로딩 실패
