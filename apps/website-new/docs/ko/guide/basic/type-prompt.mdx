# 타입 힌트

{props.name || 'Module Federation'} 산출물은 원격 CDN에 배포되어 있어도 NPM 패키지처럼 타입을 생성하고 타입 핫 리로드를 사용할 수 있습니다.

<code>{props.pkgName || '@module-federation/enhanced'}</code>는 기본적으로 타입 힌트를 활성화합니다. 이 문서에서는 자주 사용하는 시나리오와 필요한 설정을 정리합니다.

## 사용 시나리오

### 타입 생성

<code>{props.pkgName || '@module-federation/enhanced'}</code>가 제공하는 빌드 플러그인으로 빌드하면 타입 파일이 자동으로 생성됩니다.

### 타입 로딩

1. Consumer의 `tsconfig.json`에 `paths`를 추가합니다.

```json
{
  "compilerOptions": {
    "paths": {
      "*": ["./@mf-types/*"]
    }
  }
}
```

2. 애플리케이션을 시작합니다.

시작 후 consumer가 producer의 타입 파일을 자동으로 가져옵니다.

:::tip
Producer와 consumer의 시작 순서를 신경 쓰지 않아도 됩니다.
:::

### 타입 핫 리로드

Producer의 코드를 수정하면 consumer가 producer의 타입을 자동으로 다시 가져옵니다.

![hot-types-reload-static](@public/guide/type-prompt/hot-types-reload-static.gif)

### 런타임 API 타입 힌트

`Runtime`의 `loadRemote` 타입 힌트와 타입 핫 리로드를 사용하려면 `include` 필드에 `./@mf-types/*`를 추가하세요.

```json title="tsconfig.json"
{
  "include": ["./@mf-types/*"]
}
```

![hot-types-reload](@public/guide/type-prompt/hot-types-reload.gif)

:::info
Builder가 `webpack`인 경우 타입 업데이트로 인한 순환 컴파일을 피하려면 [watchOptions.ignored](https://webpack.js.org/configuration/watch/#watchoptionsignored)에 `**/@mf-types/**`를 추가하세요.
:::

### 서드파티 패키지 타입 추출

{props.name || 'Module Federation'}은 `exposes` 파일의 타입을 정상적으로 사용할 수 있도록 서드파티 패키지 타입을 자동으로 추출합니다.

![third-party](@public/guide/type-prompt/third-party.jpg)

### 중첩 타입 Re-export

{props.name || 'Module Federation'}은 nested remote를 지원하며, nested remote의 타입도 자동으로 추출합니다.

![nested-remote](@public/guide/type-prompt/nested-remote.jpg)

### 동적 타입 힌트

{props.name || 'Module Federation'}은 동적 타입 로딩과 핫 업데이트를 지원합니다.

![dynamic-remote-hot-types-reload](@public/guide/type-prompt/dynamic-remote-hot-types-reload-static.gif)

## FAQ

### 프로젝트에서 순환 컴파일이 발생하고 종료되지 않습니다

컴파일러가 타입 폴더 또는 `dist` 디렉터리 변경을 계속 감시하면서 발생할 수 있습니다. `@mf-types`를 ignored 목록에 추가하세요. Webpack/Rspack에서는 다음처럼 설정할 수 있습니다.

```ts
config.watchOptions = {
  ignored: ['**/node_modules/**', '**/@mf-types/**'],
};
```

### 타입 파일이 생성되지 않습니다. 원인을 어떻게 찾나요?

1. 프로젝트 시작 명령 앞에 `FEDERATION_DEBUG=true` 환경 변수를 추가합니다.
2. [dts.displayErrorInTerminal](/configure/dts.html#displayerrorinterminal)을 `true`로 설정합니다.
3. 프로젝트를 시작하고 콘솔 출력을 확인합니다.
4. 선택적으로, 콘솔에 에러가 없다면 `.mf/typesGenerate.log` 로그 파일을 확인합니다.
