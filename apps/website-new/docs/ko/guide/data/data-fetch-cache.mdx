# 데이터 캐싱

`cache` 함수는 data fetching 또는 계산 결과를 캐시할 때 사용합니다. 데이터를 세밀하게 제어할 수 있으며 클라이언트 사이드 렌더링(CSR), 서버 사이드 렌더링(SSR) 같은 시나리오에 적합합니다.

## 기본 사용법

```ts
import { cache } from '@module-federation/bridge-react/data-fetch';

export type Data = {
  data: string;
};

export const fetchData = cache(async (): Promise<Data> => {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({
        data: `[ provider ] fetched data: ${new Date()}`,
      });
    }, 1000);
  });
});
```

### 매개변수

- `fetchData`: DataLoader 안에서 사용하는 `fetchData` 함수입니다.
- `options` (선택): 캐시 설정입니다.
  - `tag`: 캐시를 식별하는 태그입니다. 캐시를 무효화할 때 사용할 수 있습니다.
  - `maxAge`: 캐시 유효 기간입니다. 밀리초 단위입니다.
  - `revalidate`: 캐시가 만료된 뒤 재검증할 시간 창입니다. 밀리초 단위이며 HTTP Cache-Control의 `stale-while-revalidate`와 비슷합니다.
  - `getKey`: 함수 인자를 기준으로 키를 만드는 간단한 캐시 키 생성 함수입니다.
  - `onCache`: 데이터가 캐시될 때 호출되는 콜백입니다. 캐시된 데이터를 직접 처리할 때 사용할 수 있습니다.

`options` 매개변수 타입은 다음과 같습니다.

```ts
interface CacheOptions {
  tag?: string | string[];
  maxAge?: number;
  revalidate?: number;
  getKey?: <Args extends any[]>(...args: Args) => string;
  onCache?: (info: CacheStatsInfo) => boolean;
}
```

### 반환값

`cache` 함수는 캐시 기능이 포함된 새 `fetchData` 함수를 반환합니다. 이 새 함수를 여러 번 호출해도 같은 작업이 반복 실행되지 않습니다.

## 사용 범위

이 함수는 DataLoader 안에서만 사용할 수 있습니다.

## 자세한 사용법

### `maxAge`

각 계산이 끝나면 프레임워크는 데이터가 캐시에 기록된 시간을 저장합니다. 함수가 다시 호출되면 `maxAge` 매개변수를 기준으로 캐시가 만료됐는지 확인합니다. 만료됐다면 `fn` 함수를 다시 실행하고, 그렇지 않다면 캐시된 데이터를 반환합니다.

```ts
import { cache, CacheTime } from '@module-federation/bridge-react/data-fetch';

const getDashboardStats = cache(
  async () => {
    return await fetchComplexStatistics();
  },
  {
    maxAge: CacheTime.MINUTE * 2,  // 2분 안에 호출하면 캐시된 데이터를 반환합니다.
  }
);
```

#### `revalidate`

`revalidate` 매개변수는 캐시가 만료된 뒤 재검증할 시간 창을 설정합니다. `maxAge` 매개변수와 함께 사용할 수 있으며, HTTP Cache-Control의 `stale-while-revalidate` 모델과 비슷합니다.

다음 예시에서 `getDashboardStats`가 2분의 유효 기간 안에 호출되면 캐시된 데이터를 반환합니다. 캐시가 만료된 상태(2분에서 3분 사이)라면 요청자는 먼저 오래된 데이터를 받고, 백그라운드에서 새 요청을 보내 캐시를 갱신합니다.

```ts
import { cache, CacheTime } from '@module-federation/bridge-react/data-fetch';

const getDashboardStats = cache(
  async () => {
    return await fetchComplexStatistics();
  },
  {
    maxAge: CacheTime.MINUTE * 2,
    revalidate: CacheTime.MINUTE * 1,
  }
);
```

#### `tag`

`tag` 매개변수는 캐시에 라벨을 붙여 식별할 때 사용합니다. 문자열 또는 문자열 배열을 사용할 수 있습니다. 이 태그는 캐시를 무효화할 때 사용할 수 있고, 여러 캐시 함수가 같은 태그를 공유할 수도 있습니다.

```ts
import { cache, revalidateTag } from '@module-federation/bridge-react/data-fetch';

const getDashboardStats = cache(
  async () => {
    return await fetchDashboardStats();
  },
  {
    tag: 'dashboard',
  }
);

const getComplexStatistics = cache(
  async () => {
    return await fetchComplexStatistics();
  },
  {
    tag: 'dashboard',
  }
);

revalidateTag('dashboard-stats'); // getDashboardStats와 getComplexStatistics의 캐시를 모두 무효화합니다.
```

#### `getKey`

`getKey` 매개변수를 사용하면 캐시 키 생성 방식을 직접 정할 수 있습니다. 예를 들어 함수 매개변수 중 일부만 기준으로 캐시를 구분하면 되는 경우가 있습니다. `getKey`는 원래 함수와 같은 인자를 받아 캐시 키로 사용할 문자열을 반환하는 함수입니다.

```ts
import { cache, CacheTime } from '@module-federation/bridge-react/data-fetch';
import { fetchUserData } from './api';

const getUser = cache(
  async (userId, options) => {
    // options에 여러 설정이 들어와도 userId만 기준으로 캐시합니다.
    return await fetchUserData(userId, options);
  },
  {
    maxAge: CacheTime.MINUTE * 5,
    // 첫 번째 매개변수(userId)만 캐시 키로 사용합니다.
    getKey: (userId, options) => userId,
  }
);

// getKey가 userId만 사용하므로 아래 두 호출은 같은 캐시를 공유합니다.
await getUser(123, { language: 'zh' });
await getUser(123, { language: 'en' }); // 캐시에 hit되며 새 요청은 발생하지 않습니다.

// userId가 다르면 서로 다른 캐시를 사용합니다.
await getUser(456, { language: 'zh' }); // 캐시에 hit되지 않아 새 요청이 발생합니다.
```

`getKey` 안에서 `generateKey` 함수를 사용해 캐시 키를 만들 수도 있습니다.

:::info

`generateKey` 함수는 객체 속성 순서가 바뀌어도 일관되고 고유한 키가 만들어지도록 보장합니다. 이를 통해 안정적인 캐싱을 유지할 수 있습니다.

:::

```ts
import { cache, CacheTime, generateKey } from '@module-federation/bridge-react/data-fetch';
import { fetchUserData } from './api';

const getUser = cache(
  async (userId, options) => {
    return await fetchUserData(userId, options);
  },
  {
    maxAge: CacheTime.MINUTE * 5,
    getKey: (userId, options) => generateKey(userId),
  }
);
```

#### `customKey`

`customKey`와 `getKey`는 모두 캐시 key를 커스터마이즈할 수 있게 해 줍니다. 차이는 **적용 범위**입니다.

- **`getKey`**는 key 중 "arguments" 부분만 바꿉니다. **함수 자체는 여전히 캐시 key 계산에 참여**합니다. 따라서 서로 다른 두 함수의 `getKey`가 같은 값을 반환해도 캐시를 공유하지 않습니다.
- **`customKey`**는 **최종 캐시 키 전체**를 반환합니다. 프레임워크의 기본 "함수 + 인자" 키를 대체하므로, **서로 다른 함수가 같은 캐시를 공유**하게 만들 수 있습니다.

:::tip 언제 사용하나요?
일부 인자만 기준으로 캐시 키를 만들면 된다면 `getKey`를 사용하세요. 서로 다른 함수 사이에서 캐시를 공유해야 하는 고급 시나리오에서는 `customKey`를 사용합니다.
:::

`customKey`는 다음 속성을 가진 객체를 받고 문자열 또는 Symbol을 반환해야 합니다. 반환된 값은 최종 캐시 키로 바로 사용됩니다.

- `params`: 캐시된 함수에 전달된 인자입니다.
- `fn`: 원래 캐시 대상 함수입니다.
- `generatedKey`: 입력 매개변수를 기준으로 프레임워크가 자동 생성한 기존 캐시 키입니다.

아래 예시는 `customKey`로 서로 다른 함수가 캐시를 공유하게 만드는 방법을 보여 줍니다.

```ts
import { cache } from '@module-federation/bridge-react/data-fetch';
import { fetchUserData } from './api';

// 서로 다른 함수라도 customKey를 통해 캐시를 공유할 수 있습니다.
const getUserA = cache(
  fetchUserData,
  {
    maxAge: CacheTime.MINUTE * 5,
    customKey: ({ params }) => {
      // 캐시 키로 사용할 안정적인 문자열을 반환합니다.
      return `user-${params[0]}`;
    },
  }
);

// 함수가 달라도 customKey가 같은 값을 반환하면 캐시에 hit됩니다.
const getUserB = cache(
  (...args) => fetchUserData(...args), // 새 함수입니다.
  {
    maxAge: CacheTime.MINUTE * 5,
    customKey: ({ params }) => {
// getUserA와 같은 키를 반환합니다.
      return `user-${params[0]}`;
    },
  }
);

// getUserA와 getUserB는 서로 다른 함수지만 customKey가 같은 값을 반환하므로,
// 같은 매개변수로 호출하면 캐시를 공유합니다.
const dataA = await getUserA(1);
const dataB = await getUserB(1); // 캐시 히트가 발생하고 새 요청을 보내지 않습니다.

// Symbol을 캐시 키로 사용할 수도 있습니다. 보통 같은 애플리케이션 안에서 캐시를 공유할 때 사용합니다.
const USER_CACHE_KEY = Symbol('user-cache');
const getUserC = cache(
  fetchUserData,
  {
    maxAge: CacheTime.MINUTE * 5,
    customKey: () => USER_CACHE_KEY,
  }
);

// generatedKey 매개변수로 기본 키를 수정할 수도 있습니다.
const getUserD = cache(
  fetchUserData,
  {
    customKey: ({ generatedKey }) => `prefix-${generatedKey}`,
  }
);
```

#### `onCache`

`onCache` 매개변수를 사용하면 히트율 같은 캐시 통계를 추적할 수 있습니다. 각 캐시 작업의 상태, 키, 매개변수, 결과 정보를 받는 콜백 함수입니다. `onCache`에서 `false`를 반환하면 캐시 히트를 막을 수 있습니다.

```ts
import { cache, CacheTime } from '@module-federation/bridge-react/data-fetch';

// 캐시 통계를 추적합니다.
const stats = {
  total: 0,
  hits: 0,
  misses: 0,
  stales: 0,
  hitRate: () => stats.hits / stats.total
};

const getUser = cache(
  fetchUserData,
  {
    maxAge: CacheTime.MINUTE * 5,
    onCache({ status, key, params, result }) {
      // status는 'hit', 'miss', 'stale' 중 하나입니다.
      stats.total++;

      if (status === 'hit') {
        stats.hits++;
      } else if (status === 'miss') {
        stats.misses++;
      } else if (status === 'stale') {
        stats.stales++;
      }

      console.log(`캐시 상태: ${status}, 키: ${String(key)}`);
      console.log(`현재 히트율: ${stats.hitRate() * 100}%`);
    }
  }
);

// 사용 예:
await getUser(1); // 캐시 미스
await getUser(1); // 캐시 히트
await getUser(2); // 캐시 미스
```

`onCache` 콜백은 다음 속성을 가진 객체를 받습니다.

- `status`: 캐시 작업 상태입니다.
  - `hit`: 캐시 히트입니다. 캐시된 내용을 반환합니다.
  - `miss`: 캐시 미스입니다. 함수를 실행하고 결과를 캐시에 저장합니다.
  - `stale`: 캐시 히트이지만 데이터가 오래된 상태입니다. 캐시된 내용을 반환하고 백그라운드에서 재검증합니다.
- `key`: 캐시 키입니다. `customKey`의 결과이거나 기본 생성 키일 수 있습니다.
- `params`: 캐시된 함수에 전달된 인자입니다.
- `result`: 결과 데이터입니다. 캐시에서 온 데이터일 수도 있고 새로 계산된 데이터일 수도 있습니다.

이 콜백은 `options` 매개변수가 제공된 경우에만 호출됩니다. 옵션 없이 캐시 함수를 사용하면 `onCache` 콜백은 호출되지 않습니다.

`onCache` 콜백은 다음 작업에 유용합니다.

- 캐시 성능 모니터링
- 히트율 계산
- 캐시 작업 로깅
- 사용자 정의 메트릭 구현

### 저장소

현재 캐시는 클라이언트와 서버 모두 메모리에 저장됩니다. 기본적으로 모든 캐시 함수가 공유하는 저장소 한도는 1GB입니다. 이 제한에 도달하면 LRU(Least Recently Used) 알고리즘으로 오래된 캐시를 제거합니다.

:::info
`cache` 함수가 저장하는 내용은 일반적으로 크지 않다고 가정하므로, 현재는 기본적으로 메모리에 저장합니다.
:::

`configureCache` 함수로 캐시 저장소 한도를 지정할 수 있습니다.

```ts
import { configureCache, CacheSize } from '@module-federation/bridge-react/data-fetch';

configureCache({
  maxSize: CacheSize.MB * 10, // 10MB
});
```
