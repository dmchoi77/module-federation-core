# Module Federation 2.0 릴리스 발표

> 2024년 4월 26일

Module Federation 2.0의 공식 릴리스를 발표합니다.
이번 버전은 [ByteDance Web Infra](https://github.com/web-infra-dev) 팀, Module Federation의 저자인 [Zack Jackson](https://github.com/ScriptedAlchemy), 그리고 여러 커뮤니티 멤버가 함께 만든 결과입니다. 특히 [@ilteoood](https://github.com/ilteoood), [@patricklafrance](https://github.com/patricklafrance), [@crutch12](https://github.com/crutch12)에게 감사드립니다.
Module Federation 2.0은 ByteDance의 내부 실전 경험과 기존 Module Federation 커뮤니티 생태계를 바탕으로, 이전 버전의 여러 문제를 해결합니다.

## 왜 Module Federation 2.0인가요?

Webpack 5에서 처음 소개된 Module Federation은 3년 넘게 중요한 기능으로 사용되어 왔습니다.
모듈 공유 솔루션으로서 특히 대규모 웹 프로젝트에서 널리 도입되었고, 큰 애플리케이션을 더 효율적이고 단순하게 개발하며 팀 협업을 개선하는 데 도움을 주었습니다.
하지만 사용 범위가 넓어지면서 새로운 과제도 나타났습니다.

2.0 버전은 다음 개선 사항으로 이러한 과제를 해결합니다.

- **모범 사례**: 새로운 독립 문서 사이트인 [module-federation.io](https://module-federation.io/)에서 모범 사례와 설정 방법을 제공합니다.
- **런타임과 빌드 도구 분리**: 런타임을 빌드 도구에서 분리해 여러 플랫폼에서 구현을 표준화하고 모듈 로딩의 유연성을 높였습니다.
- **타입 안전성**: 업데이트된 빌드 플러그인이 TypeScript 프로젝트의 타입을 자동으로 생성하고 로드합니다. 개발 모드에서는 타입을 동기화해 안전성을 높입니다.
- **디버깅 도구**: 새로운 Chrome DevTools로 디버깅이 더 편리하고 효율적이 됩니다.
- **배포 플랫폼**: `mf-manifest.json` 파일 프로토콜이 추가되어 배포 플랫폼과의 통합이 단순해지고, 버전 리소스를 더 잘 관리할 수 있습니다.

## Module Federation 2.0 기능 소개

### 새 문서 사이트

새 문서 사이트는 Module Federation을 적용할 수 있는 시나리오와 기능을 자세히 소개합니다. Rspack으로 프로젝트를 시작하는 과정부터 기능을 활용하는 방법까지 전체 흐름을 다루며, 플러그인 설정도 깊이 있게 설명합니다.

![](@public/blog/announcement/module-federation-doc.png)

### 더 유연한 모듈 로딩

업데이트된 버전에는 중요한 변화가 있습니다. 기존에 Webpack 안에 포함되어 있던 런타임 기능을 독립 SDK로 분리했습니다. 덕분에 특정 빌드 도구에 의존하지 않고 remote 모듈과 shared modules를 동적으로 등록하고 로드할 수 있습니다. 또한 모듈 프리로딩과 런타임 플러그인 기능이 강화되어 모듈 로딩 과정을 더 강력하게 제어할 수 있습니다.

```typescript
import { init, loadRemote } from '@module-federation/enhanced/runtime';

init({
  name: '@demo/app-main',
  remotes: [
    {
      name: "@demo/app1",
      entry: "http://localhost:3005/mf-manifest.json",
      alias: "app1"
    },
    {
      name: "@demo/app2",
      entry: "http://localhost:3006/remoteEntry.js",
      alias: "app2"
    },
  ],
});

loadRemote("app2/util").then((md)=>{
  md.add(1,2,3);
});
```
### Webpack 분리와 빌드 도구 간 모듈 공유 지원

새 Module Federation 플러그인은 완전히 새로운 런타임 아키텍처를 채택했습니다. 이제 빌드 도구와 런타임이 강하게 결합되지 않습니다. 개발자는 서로 다른 빌드 도구가 만든 산출물을 프로젝트에 자유롭게 가져와 유연하게 조합하고 실행할 수 있습니다.

현재 Webpack과 Rspack을 포함한 여러 빌드 도구가 이 방식과 호환됩니다. 다른 빌드 도구도 이 표준을 기반으로 Module Federation을 구현할 수 있으며, 이를 통해 런타임의 일관성과 표준화를 유지할 수 있습니다.

### 타입 힌트

새 버전은 획기적인 기능인 동적 모듈 타입 힌트를 제공합니다. 이 기능은 TypeScript 프로젝트에서 로컬 모듈을 동적 remote 모듈로 전환할 때 타입이 손실되는 문제를 효과적으로 해결합니다. 이제 이 플러그인을 사용하면 remote 타입을 자동으로 생성하고 사용할 수 있을 뿐 아니라, 모든 프로젝트가 로컬에서 실행 중일 때 npm link와 비슷한 실시간 타입 업데이트 경험도 얻을 수 있습니다.

![](https://module-federation-assest.netlify.app/document/announcement/blog/announcement/demo-type-hint.gif)

### Chrome DevTools

DevTools는 Module Federation을 위해 개발된 디버깅 도구입니다. 모듈 간 의존성은 물론 `exposes`와 `shared` 설정을 명확하게 보여 줍니다. 또한 온라인 페이지의 모듈을 로컬 개발 환경으로 프록시하면서 HMR을 유지해 더 부드러운 개발 경험을 제공합니다.

![](https://module-federation-assest.netlify.app/document/announcement/blog/announcement/chrome-devtool-display.gif)

### Manifest 프로토콜

Module Federation의 빌드 플러그인은 Manifest 파일을 생성합니다.
이 파일에는 remoteEntry, shared, exposes, remotes, chunks, 타입 같은 시스템의 기본 정보가 들어 있습니다.
이 정보는 프로젝트 간 의존성을 분석하는 기반이 되며, 플랫폼을 빌드하고 최적화하는 데 도움을 줍니다.
이를 통해 여러 배포 플랫폼에서 모듈의 세밀한 버전 관리와 단계적 릴리스 관리가 가능해집니다.
또한 빌드 플러그인과 런타임은 Manifest 파일 프로토콜을 직접 사용해 더 고급 기능을 구현할 수 있습니다.
예를 들어 최신 버전의 동적 타입 힌트 기능은 Manifest 파일 프로토콜을 기반으로 개발되었습니다.

![](https://module-federation-assest.netlify.app/document/announcement/blog/announcement/manifest-file.gif)

## 감사의 말

Module Federation 새 버전의 개발은 커뮤니티의 여러 프로젝트가 준 영감과 지원 없이는 불가능했습니다.
다음 프로젝트에 깊은 존중과 감사를 전합니다.

- [Webpack Module Federation](https://webpack.js.org/concepts/module-federation/): 새 Module Federation은 이를 포크한 뒤 기반 구조를 재설계하고 구현했습니다.
- [Module Federation Universe](https://github.com/module-federation/core) 저장소: Universe의 기존 구현은 새 Module Federation의 토대가 되었습니다.
- [Rspack](https://github.com/web-infra-dev/rspack) 프로젝트: Rspack 팀은 Module Federation 런타임을 기반으로 Module Federation을 구현해 2.0이 Rspack 생태계와 완전히 호환되도록 했습니다.

## 향후 계획

### 개발자 경험 개선

새 버전에는 동적 타입 힌트와 Chrome DevTools 지원이 도입됐지만, 현재 Chrome DevTools 기능은 아직 충분하지 않습니다.
앞으로 공유 재사용 시각화 기능을 추가하는 등 Module Federation 디버깅 도구를 개선할 계획입니다.

### 고성능 솔루션 제공

마이크로 프론트엔드 아키텍처 솔루션인 Module Federation도 마이크로 프론트엔드 특유의 "요청 워터폴 문제"를 마주합니다.
이 문제를 해결하기 위해 Module Federation은 Server-Side Rendering(SSR), 데이터 프리패칭을 포함한 여러 고성능 전략을 제공할 계획입니다.

### 커뮤니티 파트너와 협력

Module Federation 2.0의 새 기능은 현재 Webpack과 Rspack 두 빌드 도구에서만 지원됩니다. Module Federation은 다양한 기본 SDK를 제공하므로 다른 빌드 도구도 이를 기반으로 확장하거나 감쌀 수 있습니다. 현재 Module Federation은 주로 모듈 공유 솔루션으로 사용되지만, 앞으로는 상위 프레임워크와 결합해 Module Federation 기반 마이크로 프론트엔드 아키텍처 모범 사례를 제공할 계획입니다. 이를 통해 개발자는 대형 웹 애플리케이션의 마이크로 프론트엔드 아키텍처 요구사항에 더 잘 대응할 수 있습니다.
