{props.name || 'Module Federation'}은 Node.js 환경을 기본으로 지원합니다. 런타임에서 모듈만 소비하든, Webpack/Rspack 빌드 파이프라인에 통합하든, 비교적 적은 설정으로 도입할 수 있습니다. 이 문서에서는 Node.js에서 {props.name || 'Module Federation'}을 사용하는 대표적인 방법을 다룹니다.

## 개요

Node.js 서버 애플리케이션에서는 {props.name || 'Module Federation'}을 통해 remote 모듈을 불러올 수 있습니다. 이 모듈은 CommonJS 형식으로 빌드된 로컬 파일일 수도 있고, HTTP로 접근하는 remote 서비스일 수도 있습니다. 이를 기반으로 서버 사이드 마이크로서비스, 동적 기능 제공, 공유 리소스 구성을 유연하게 만들 수 있습니다.

## Consumer

### 런타임 전용

Node.js에서 모듈을 소비하기만 하고 Webpack/Rspack 같은 번들러를 도입하고 싶지 않다면 런타임 전용 방식으로 사용할 수 있습니다. 핵심은 **빌드 플러그인이 필요 없다는 것**입니다. { props.runtime || '@module-federation/runtime' }이 제공하는 API만 사용하면 됩니다.

진행 순서는 다음과 같습니다.

1. `createInstance`로 MF 인스턴스를 만듭니다.
2. `remotes` 배열로 remote를 등록합니다.
3. `loadRemote`로 모듈을 불러옵니다.

다음 예시는 HTTP로 노출된 remote 모듈을 불러오는 방법을 보여 줍니다.

{props.runtimeConsumerDemo || <RuntimeConsumerDemo />}

### 번들러 플러그인 사용하기(Rspack/Webpack)

Node.js 애플리케이션이 Webpack 또는 Rspack으로 빌드된다면, 플러그인과 필요한 런타임 설정을 추가하는 방식으로 {props.name || 'Module Federation'}을 통합할 수 있습니다.

host(consumer)에서는 `@module-federation/node/runtimePlugin`을 추가하고 `remoteType: 'script'`, `target: 'async-node'`를 설정한 뒤 나머지 설정을 적용합니다.

## FAQ

### 1. `target: 'async-node'`는 무엇을 하나요?

`target: 'async-node'`는 Node.js에서 비동기 로딩에 적합한 결과물을 생성하는 Webpack 빌드 대상입니다. Module Federation은 동적이고 비동기적인 로딩 모델을 사용하므로, 특히 remote를 불러오는 동안 top-level `await`가 필요한 경우 이 설정이 중요합니다.

### 2. 왜 `remoteType: 'script'`를 설정해야 하나요?

현재 MF 번들러 런타임은 Node.js 소비 시 `script` remote 로딩 타입을 사용합니다. 따라서 Node.js에서 remote를 소비하려면 `remoteType: 'script'`를 명시해야 합니다.
